# CLAUDE.md

Guidance for Claude sessions working on this repo. Read [README.md](README.md) first for features, file layout and the roadmap.

## Project facts

- SwiftUI, one multiplatform target (macOS / iOS / visionOS), deployment target 27.2, Xcode 27.2.
- New-format project file `SwiftAIDocumentClassifier.xcodeproj/project.xcproj` with a **folder-synchronized** group: add `.swift` files to `SwiftAIDocumentClassifier/` and they compile. Don't edit the project file to register them.
- Build settings that affect code: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, `SWIFT_APPROACHABLE_CONCURRENCY = YES`, Swift 5 language mode, App Sandbox on with `ENABLE_USER_SELECTED_FILES = readonly` (the file importer relies on it).
- `README.md` and `CLAUDE.md` are listed in the project file without target membership, so they show in Xcode's navigator but aren't copied into the app bundle. Keep it that way.
- One package dependency: GRDB 7 (`packages` and `package-product-members` in `project.xcproj`; resolved versions in `SwiftAIDocumentClassifier.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`, which should be committed). No tests yet, and it isn't a git repository yet either.

## Verifying changes

- Build **both** macOS and iOS Simulator (commands in the README). macOS-only APIs must sit behind `#if os(macOS)`, for example `VSplitView`, `navigationSubtitle`, `.tableStyle(.inset(alternatesRowBackgrounds:))`.
- Keep the build at zero warnings. Example already hit: passing a main-actor static method as a function reference (`urls.compactMap(Self.makeDocument)`) warns; use a closure.
- SourceKit in some editors reports bogus "Cannot find type … in scope" errors for this project format. Trust `xcodebuild`, not those diagnostics.
- Xcode's static preview snapshots don't capture `PDFView` page contents (PDFKit draws tiles asynchronously), so the "PDF" preview shows the controls over a blank page; check PDF rendering in the running app.
- Check UI changes visually (Xcode previews: `ContentView.swift` has a 1200×780 `#Preview`), not just by compiling.
- Non-UI code (library, renditions, zoom logic) can be tested quickly outside Xcode by compiling the file with a small `main.swift` harness: `swiftc -default-isolation MainActor -enable-upcoming-feature NonisolatedNonsendingByDefault -swift-version 5 File.swift main.swift`. Keep harnesses in `/tmp`, not the repo.
- Database code needs GRDB, so test it with a SwiftPM package in `/tmp` instead: an executable target with symlinks to `LibraryDatabase.swift`, `Models.swift`, `SampleData.swift` and `DocumentLibrary.swift`, a `.package(path:)` dependency on the GRDB checkout in DerivedData (`SourcePackages/checkouts/GRDB.swift`), and `swiftSettings: [.defaultIsolation(MainActor.self), .swiftLanguageMode(.v5), .enableUpcomingFeature("NonisolatedNonsendingByDefault")]`. Point `DocumentLibrary(root:)` at a `/tmp` folder. Use `swift run -c release` for timings.
- On macOS, Xcode previews also launch the app's `WindowGroup`. `ClassifierStore.load()` therefore uses an in-memory database when `XCODE_RUNNING_FOR_PREVIEWS` is set; previews themselves use `ClassifierStore.preview(selecting:)`. Never let previews open the real library.
- Device Interaction can't drive macOS apps, and this Mac has no iOS Simulator runtime installed, so UI flows are checked by hand or with `RunCodeSnippet` on `ClassifierStore.preview()`.

## Code conventions

- State lives in `ClassifierStore` (`@Observable`), created once per window in `ContentView` and passed down; views take `@Bindable var store` when they need bindings. Every window's store shares one `LibraryDatabase` (opened once per process in `ClassifierStore.openDatabase`).
- `Document` keeps file metadata as typed properties (`name`, `kind`, `added`, `sizeBytes`, `pages`, `md5`) and extracted values in `values[String: String]` keyed by `SchemaField.key`. `document[key]` gives the display string for both; meta keys are in `MetaKey` (`_name`, `_kind`, `_added`, `_size`, `pages`, `md5`).
- `DocumentFolder.fields` excludes the Name column; `DocumentTable` always adds Name first. The inbox (`isInbox`) uses meta keys as its fields and cannot be edited.
- Everything the app stores on disk goes under `DocumentLibrary.root`: originals in `Files/`, generated PDFs in `Renditions/`, the SQLite DB (`library.sqlite`) at the root. Files are named by SHA-256. Anything that writes there must call `store.librarySize.setNeedsUpdate()` so the sidebar size stays current, because there is no file-system watcher. (Sample-document PDFs are generated into the temp directory, not the library.)
- Concurrency: with approachable concurrency, a `nonisolated async` function runs on the caller's actor, so it does **not** move work off the main thread. Mark blocking work `@concurrent` (see `LibrarySizeMonitor.measure`), and mark value types used there `nonisolated`. The model types in Models.swift and `SampleData` are `nonisolated` because database closures (and the seeding migration) use them.
- Import accepts PDFs and images (the design's original scope), plus Word, OpenDocument and RTF on macOS only, because iOS can't read those formats.
- Anything multi-page is shown as a PDF in `PDFStage` (originals, or renditions from `DocumentRendition`), so paging, zoom and the page indicator behave the same for every type. Single-page content uses `ZoomableStage`. "Fit" differs by design: `ZoomableStage` fits the whole page, `PDFStage` fits the width (like Preview's continuous mode).
- AI uses **only the on-device `SystemLanguageModel`** (never `PrivateCloudComputeLanguageModel`). This is a product requirement. Read `contextSize` at runtime (8192 on the dev Mac, not the documented 4096) and trim document text with `tokenCount` (`DocumentClassifier.fittedBody`). OCR is Vision's `RecognizeDocumentsRequest`.
- Prompt rules learned by measuring on the model (keep them unless re-measured): extraction fields are **required, nullable strings** (`anyOf: [String, .null]`) converted in code, because numeric schemas invent numbers and optional properties make the model skip or reorder fields; **no number-format wording** in field hints or descriptions ("write it as a number" or "as a number only" make it drop amounts); greedy sampling plus `maximumResponseTokens` (stops runaway answers that overflow the context). "Sufficient information" = at least `DocumentClassifier.minimumFieldCoverage` (50 %) of the type's fields extracted. Reclassifying never touches a document whose outcome is its current type (`ClassifierStore.fileAndReport`).
- Proposals: the on-device model only sometimes adds a Period field for per-period amounts, so `DocumentClassifier.addPeriodFieldIfNeeded` adds one when the text says "per month", "/mo", "annually" and so on, the proposal has a decimal field, and no field names a period or frequency.
- To check prompt changes, run the samples through `DocumentClassifier` in a `/tmp` harness (it calls the real model from the command line) and compare classifications and values before/after.
- Zoom state is one `PreviewZoom` per `DocumentPreview`, published with `focusedSceneValue` for the View-menu commands; it resets to fit when the selected document changes.
- Saving a type (`ClassifierStore.updateType`) deletes the values of removed fields (keys no longer in the schema) from all of its documents; the type sheet shows a warning with the affected document count before Apply. Field keys are stable, so renaming a field keeps its values.
- Numeric fields store only the number, formatted like `1,500.00` (no currency or units). Periods are modeled as a separate Text field (sample: Contracts "Value" + "Period"). Everything that writes values enforces this: AI extraction (`DocumentClassifier.displayValue` discards answers without a number), the value editor (`FieldType.numberFromInput`, with input filtered to `FieldType.numberInputCharacters`), type changes (`FieldType.convertedValue`) and the sample data (`SampleData.number`). Printed sample pages keep their currency symbols because they stand for the documents.
- Changing a field's data type converts existing values with `FieldType.convertedValue(_:)` (Models.swift); values it can't convert are removed. Numbers need exactly one number in the text, so a date never becomes a number. `ClassifierStore.convertValues` runs write transactions of 1,000 documents (`LibraryDatabase.convertValues`, off the main actor), publishing `schemaUpdate` between them so `SchemaUpdateOverlay` can show progress; the window is disabled meanwhile, and each batch skips documents that have left the type. 10,000 date-to-timestamp conversions take about 2 s, mostly date parsing.
- Drag and drop: table rows are draggable (`TableRow.draggable(DocumentDragItem)`, a document ID sent as tagged text so no Info.plist type is needed) and sidebar rows are drop destinations (`dropDestination(for:isEnabled:action:)` on `SidebarView.FolderRow`). The row's label fills the full row with a rect content shape so the whole row is the target, draws its own accent highlight from `onDropSessionUpdated` (phase `.entering` / `.active`), and declares `.move` via `dropConfiguration` so the cursor shows no "+" copy badge. A drop calls `ClassifierStore.assign(_:to:)`, which moves the document with empty values and then only extracts the target type's fields; it never classifies or suggests. Model requests are serialized through `classificationProgress` (assign waits for it to clear).
- Column alignment follows `FieldType` (`isNumeric` → `.numeric` alignment). Sorting happens in SQL on typed sort keys (see Persistence); `DocumentComparator` is only the `Table` sort descriptor and converts to `DocumentSort`.
- Prefer native macOS idioms over pixel-copying the HTML prototype: system accent color, SF Symbols, `ContentUnavailableView`, `.sheet`, `.fileImporter`, semantic colors (dark mode works). The rendered "paper" in the preview deliberately uses fixed light colors.
- Match existing style: small private helper views/functions, `// MARK:` sections, doc comments only where intent isn't obvious.
- Docs (README, CLAUDE.md): never use em dashes. Write with regular English grammar and punctuation (commas, colons, semicolons, parentheses, separate sentences).

- Window 1200×780; sidebar 232 pt wide; inspector 282 pt; preview pane ~330 pt tall; paper sheet 300×≤286 pt (receipt 220 pt, monospaced).
- Sidebar: inbox row, then a "Document Types" header; folder rows show a count badge; "New Type" at the bottom.
- Toolbar: folder title + "N documents", pencil (edit type, hidden for the inbox), "AI Classify" in the inbox / "AI Reclassify" in types (same action; while running it keeps its size, is disabled and its symbol pulses; never put variable-width content in the toolbar), "Add Documents", info button, search "Search <folder>". - Type sheet: title "New Document Type" / "Edit Document Type" / "Suggested Document Type" (with the reason, a "Classify as Existing Type" menu with the closest match first, and "Create & Classify"); type name, then a type description; field rows = name + data-type picker stacked in a 196 pt column, description editor beside them, red minus to remove; "Add Field"; Cancel + Create/Apply (disabled when the name is empty or duplicates another type, case-insensitive). New types start with one blank field; blank-named fields are dropped on submit.
- Preview pane: zoom controls float at the bottom (− / percentage menu / +, plus "Page N of M" for paged documents). Inspector: file name header (no icon, because the preview already shows the file), then "File" facts for the inbox or "Extracted Fields" + "General" for typed folders. "Extracted Fields" has an accent-colored "Edit" button (hidden when the type has no fields) that opens the "Edit Values" sheet: one scrolling row per field with its name, data-type badge, description and an editor. Text and number fields use a text field whose placeholder shows the expected format. Date and Timestamp fields use a compact `DatePicker` (plus a calendar popover button on macOS, where the compact style is only a text field) and a clear button; empty shows "Set Date", unparseable text shows a warning. Dates are still stored as text (`DateFormatter.documentDay` / `documentStamp`) and parsed with `DateFormatter.documentDate(from:)`, shared with the classifier; "Discard" and "Apply" (disabled until something changes). Empty values are removed.
- Empty folder: "No Documents" / "Documents classified as **<name>** will appear here." / "N fields will be extracted from each document."

## Persistence

Built from the design agreed with the user (the roadmap's former item 1). Keep to it unless they change it.

### Design as built

- SQLite via GRDB (`DatabasePool`, WAL mode) at `DocumentLibrary.root/library.sqlite`, so `LibrarySizeMonitor` counts it and its `-wal`/`-shm` files. All database work goes through `LibraryDatabase` (`nonisolated final class`, `Sendable`), which uses GRDB's async `read`/`write`, so it never runs on the main actor. Opening and migrating is `@concurrent`. Files stay copied into the library (no bookmarks).
- Migration `"v1"` creates every table and seeds `SampleData.folders()` (types, fields and documents with `is_sample = 1`, `content_kind = 'sample'`). Seeding happens only in that migration, so it never reseeds. `SampleData.folders()` returns `SampleData.Seed` values (a folder plus its documents) and harnesses keep using it directly.
- Tables:
  - `document_type(id TEXT PRIMARY KEY, name, description, position)` with today's string IDs (`"invoices"`, `"t_ab12cd34"`).
  - `schema_field(type_id, key, label, data_type, description, width, position, PRIMARY KEY (type_id, key))`. **Deviation:** the plan had `key` as the primary key, but keys repeat across types (several sample types have `vendor`, `amount` or `date`). As a result `field_value` has no foreign key to `schema_field`; `LibraryDatabase.saveType(_:removing:)` deletes removed fields' values from the type's documents explicitly.
  - `document(seq INTEGER PRIMARY KEY, id TEXT NOT NULL UNIQUE, type_id NULL, name, kind, added_at, size_bytes, pages, md5, content_kind, file_path, rendition_path, sample_page, is_sample, suggested_type_id, confidence)`. **Deviation:** `seq` was added as a stable integer rowid for the FTS row (an implicit rowid can change on VACUUM); `id` is unique rather than the primary key. `type_id IS NULL` means Unclassified. Index `(type_id, added_at)`. `added_at` is seconds since 1970. `suggested_type_id` and `confidence` are not written yet.
  - `field_value(doc_id, field_key, display, sort_num, sort_text COLLATE NOCASE, PRIMARY KEY (doc_id, field_key)) WITHOUT ROWID`, indexes `(field_key, sort_num)` and `(field_key, sort_text)`, foreign key to `document` with `ON DELETE CASCADE`.
  - `document_text(doc_id, source, text)`, created but empty (roadmap item 1).
  - `search`: FTS5 with `content=''`, `contentless_delete=1` (so rows can be deleted by rowid) and `tokenize='trigram remove_diacritics 1'`. One row per document (rowid = `document.seq`) holding the name and every value. `LibraryDatabase.writeValues` rewrites it (`rewriteSearchRow`) in the same transaction as any change to a document's values; a trigger deletes it with the document.
- The inbox is not a type row. `DocumentFolder.inbox` is virtual, and `"inbox"` becomes `type_id IS NULL` only inside `LibraryDatabase` (`typeID(forFolderID:)`). Inbox columns sort by `document` columns (`metaColumns`).
- IDs: `Document.id` is a stored `var id = UUID()`, saved as uppercase text.
- Content: `content_kind` is `pdf`, `image`, `file` or `sample`; `file_path` and `rendition_path` are relative to the root, and URLs are rebuilt on read. `.image(URL)` is decoded only when shown or read (`DocumentReader.loadImage`, `@concurrent`, applies EXIF orientation); `PrintedPage` is stored as JSON in `sample_page`.
- Values: `field_value.display` is the canonical string. `FieldType.sortKeys(for:)` (Models.swift) computes the sort keys on every write: date and timestamp as epoch seconds, numbers without grouping commas, text in `sort_text`. Unparseable values get no keys and sort with empty ones.
- Leftover files: when `open` reports that it created the database, `ClassifierStore.recoverLeftoverFiles` imports every unreferenced `Files/` entry into Unclassified through the normal import path (as `Recovered <8 hex>.<ext>`), then deletes unreferenced `Renditions/` files. It runs once, never on later launches.

### How the app uses it

- `ClassifierStore` holds `folders` (inbox plus types and fields; `DocumentFolder.docs` is gone), `counts` for the sidebar badges, and only the selected folder's `rows` (newest first) with `rowsFolderID` and `rowsRevision`. Changing `selectedFolderID` reloads; overlapping reloads are resolved by a generation counter. Every write reloads the rows and counts explicitly (no `ValueObservation`) and calls `librarySize.setNeedsUpdate()`.
- `FolderDetailView` keeps `orderedIDs`: with a search or sort it runs `LibraryDatabase.documentIDs(in:matching:sortedBy:)` in `.task(id:)` (searches debounced 150 ms) and maps the IDs onto loaded rows. Searches of 3 or more characters use FTS5 `MATCH` with the query as one quoted phrase; 1 to 2 characters use `LIKE` on the name and `field_value.display`. Sorting by a field uses `LEFT JOIN field_value` on `sort_num` or `sort_text`, NULLs last, then name.
- `ValueEditorTarget` carries a snapshot of the `Document`. The type sheet counts affected documents with `ClassifierStore.documentCount(in:withValuesFor:)`.
- Selection stays per folder in memory (`selectedDocByFolder`) and falls back to the first row when the stored ID isn't loaded.
- Measured with 10,000 documents in one type (release build, off the main thread): loading the folder takes 35 ms (`DocumentRecord.init(row:)` decodes by hand, about three times faster than `Decodable`), sorting takes 6 to 11 ms, a search keystroke takes 1 to 10 ms, and mapping IDs to rows on the main thread takes about 2 ms.
